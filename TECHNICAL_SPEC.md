## 1. Подсистема автора

**Ключевые файлы:** `fb2_author_extractor.py`, `name_normalizer.py`,
`passes/pass2_series_filename.py`, `passes/pass4_consensus.py`

### 1.1 Источники и приоритет

| Приоритет | Источник | `author_source` |
|-----------|----------|-----------------|
| 1 (высший) | Структура папок (автор/серия) | `folder_dataset` |
| 2 | Имя файла | `filename` |
| 3 | FB2-метаданные (`<author>`) | `metadata` |

Источник `folder_dataset` никогда не перезаписывается на последующих шагах.

---

### 1.2 Источник 1: Структура папок

**Где:** `pass2_series_filename.py` → `_propagate_ancestor_folder_authors()`, выполняется *до* основного цикла.

**Алгоритм:**
1. Для каждого файла проходит по всем папкам-предкам (от корня к файлу), пропуская технические папки (fb2, epub — список `FILE_EXTENSION_FOLDER_NAMES`).
2. Для каждой папки вызывает `parse_author_from_folder_name()`.
3. **Валидация:** слово из имени автора должно присутствовать в `male_names`/`female_names`, либо должен совпасть паттерн инициала `А.Фамилия`.
4. **Кросс-проверка с метаданными:** если у файла есть `metadata_authors` — хотя бы одно слово из автора папки должно встречаться в мете. Исключение: мета содержит коллективные термины (Соавторство, Сборник, [unknown]).
5. Слова «и др.», «et al.» удаляются из имени.

Дополнительно, в `fb2_author_extractor.py` → `_extract_author_from_folder_structure()`:
- Поднимается по папкам на `folder_parse_limit` уровней вверх.
- Сначала ищет паттерн `(Автор)` в скобках в начале или конце имени папки.
- Fallback: `author_processor.extract_author_from_filepath()`.

**Верификация против метаданных** (`_verify_author_against_metadata()`):
- Стратегия 1: точное совпадение строк.
- Стратегия 2: перекрытие слов ≥50%.
- Стратегия 3: `SequenceMatcher` с порогом ≥0.70.

---

### 1.3 Источник 2: Имя файла

**Где:** `fb2_author_extractor.py` → `_extract_author_from_filename()`

**Порядок попыток:**
1. Явный автор в скобках в конце имени: `\(([^)]+)\)$` → проверка `_is_valid_author_candidate()`.
2. Динамический паттерн-матчинг через `_select_best_pattern()` — перебор паттернов: «Author - Title (Series)», «Author. Title (Series)» и др. Автор — group 1 (или group 2 для «Title (Author)»).
3. Fallback: `author_processor.extract_author_from_filename()`.

**Валидация кандидата** (`_is_valid_author_candidate()`):
- Не в blacklist (`filename_blacklist` из конфига).
- Содержит буквы; не полностью UPPERCASE; длина 2–100.
- Либо содержит известное имя из `male_names`/`female_names`, либо структурно выглядит как имя (2+ слова с заглавной буквы).
- Не выглядит как название серии (`_looks_like_series_description()`).

**Расширение сокращений** (если автор неполный — одно слово или аббревиатура):
1. Поиск по частичному имени в серии (`all_series_authors_str`).
2. Поиск по частичному имени в метаданных файла.
3. Расширение фамилий из серии через `_expand_surnames_from_metadata()`.
4. Расширение из метаданных текущего файла.
5. Расширение из первого автора метаданных.

---

### 1.4 Источник 3: FB2-метаданные

**Где:** `fb2_author_extractor.py` → `_extract_author_from_metadata()`

- Читает только блок `<title-info>` (до 65 536 байт).
- Парсит теги `<first-name>` и `<last-name>` (поддерживает `fb:` namespace). `<nickname>` и `<middle-name>` игнорируются.
- Имя формируется как `"{first_name} {last_name}".strip()`.
- Проверяется через `_is_blacklisted()` (word-boundary matching).

**Определение кодировки** (`_detect_correct_encoding()`):
BOM → XML declaration → попытка UTF-8 (строгая) → эвристика по «естественности» кириллицы.
Кандидаты: koi8-r, cp1251, cp866.

---

### 1.5 Нормализация имени автора

**Где:** `name_normalizer.py`, класс `AuthorName` + `fb2_author_extractor.py` → `_normalize_single_author()`

1. Замена ё→е, NFC-нормализация.
2. Исключения: «Фамилия А.Я.» — оставляется; «Псевдоним (ИмяФамилия)» — целиком.
3. **2 слова:** определение порядка через `male_names`/`female_names`. Если первое слово — имя, второе — не имя → переставить. Оба в списке или ни одного → оставить. Эвристика по суффиксам фамилий (-ов, -ева, -ский, -ин…), по соотношению гласных/согласных.
4. **3+ слов:** поиск отчества (-ович/-евич/-овна/-евна), обработка частиц (де, ван, фон), детекция инициалов.
5. Специальный токен «Коллектив авторов» → «Сборник».

**Правило множественных авторов** (`_normalize_author_count()`):
- ≤2 авторов: нормализуем каждого, сортируем по алфавиту, соединяем запятой.
- >2 авторов: возвращаем «Соавторство».

---

### 1.6 Консенсус авторов (Pass 4)

**Где:** `passes/pass4_consensus.py`

**Author consensus:** `series_processor.apply_author_consensus()` — группировка по папке, большинство авторов применяется к файлам без определённого источника.

**Series author consensus:** для серий с ≥2 файлами — находит самого частого автора. Правила перезаписи:
- `folder_dataset` — никогда не трогать.
- `filename`: перезаписывать только если текущий автор является *подмножеством* консенсусного (например «Ипатова» → «Ильин, Ипатова»).
- `metadata`/`consensus`: подмножество → перезаписать; уникальный (count=1) → не трогать.
- Порог: 80%.

**Filename prefix author consensus:** для файлов без автора в папке — если stem файла начинается с известного имени автора из той же папки (с нормализацией кириллица/латинские lookalike) → устанавливается этот автор.

## 2. Подсистема серии

**Ключевые файлы:** `passes/pass2_series_filename.py`, `passes/pass3_series_normalize.py`,
`passes/pass4_consensus.py`, `block_level_pattern_matcher.py`, `series_normalizer.py`

### 2.1 Источники и приоритет

| Приоритет | Источник | `series_source` |
|-----------|----------|-----------------|
| 1 (высший) | Явная папка автора/серии | `folder_dataset` |
| 2 | Папка с подтверждением меты | `folder_metadata_confirmed` |
| 3 | Папка-иерархия | `folder_hierarchy` |
| 4 | Имя файла + мета совпадают | `filename+meta_confirmed` |
| 5 | Только имя файла | `filename` |
| 6 | Только FB2-метаданные | `metadata` |
| 7 | Назначена консенсусом | `consensus` / `author-consensus` |

---

### 2.2 Pass 2: Извлечение серии

**Где:** `passes/pass2_series_filename.py` → `execute()`

#### Шаг А: Серия из структуры папок

Для каждого файла ищется папка автора в цепочке пути. Два уровня сопоставления:
- Строгое: прямое вхождение строк.
- Слабое: `_author_matches_folder()` — совпадение слов, формы множественного числа, несколько авторов через «и».

При нахождении папки автора на позиции `i`:
- `path[i+1]` — папка серии (обычный случай) → `series_source = "folder_hierarchy"`.
- `path[i+2]` существует → `"Серия\Подсерия"` (иерархия).
- Папка «Вне серий» (`is_no_series_folder`) → `series_source = "no_series_folder"`, серия пустая.
- Вариантная папка (`_is_variant_folder`) → серия из самой папки автора.
- Защита от «издательских папок»: если папка содержит слово автора → серия не устанавливается из папки.

#### Шаг Б: Серия из имени файла (`_extract_series_from_filename()`)

Предобработка: удаление тегов `(СИ)`, `(ЛП)`, год-суффиксов (1900–2099).

**Шаг 0 (двухуровневая иерархия):** regex-паттерны для структур «Серия N. Подсерия M. Название» (варианты А–Г). Требуют подтверждения через `metadata_series`. Возвращают `"Серия\Подсерия"`.

**Шаг 1: BlockLevelPatternMatcher:**
- Использует паттерны из конфига.
- Паттерн без слова «Series» → результат игнорируется.
- При наличии `metadata_series`:
  - Совпадают → возвращаем через `_extract_main_series_from_multi_level`.
  - Не совпадают, но мета подтверждает компонент иерархии → возвращаем root или полную иерархию.
  - Score ≥0.85, не совпадают → возвращаем только root (без подсерии).
- Без метаданных: без SubSeries в паттерне и без сервисного слова в конце → возвращаем только root.

**Шаг 2: BlockLevelPatternSelector (резервный):**
- `analyze_filename_blocks()`: разбивает имя на скобочную часть и часть до скобок.
- `score_blocks()`: оценивает соответствие. Жёсткие дисквалификаторы (−999). Штраф за несовпадение уровней иерархии в скобках.

**Правило 3 (fallback «Author. Series NUM»):**
- Разбить по первой точке. Первая часть — автор (<50 символов, без цифр). Вторая — кандидат на серию, должна заканчиваться числом (N, N-M, римские).
- Совпадение с `file_title` (кандидат = название книги) блокируется, если нет диапазона.

**Правило 4 (fallback «Author - Series NUM»):**
- Разделитель ` - `. Аналогичная логика + обрабатывает «Author - Series N. Title».

**После получения кандидата:**
- Проверка на запятую (список авторов vs грамматическая).
- `_is_author_surname()`: кандидат не должен быть фамилией/именем автора.
- **Title-as-series guard:** кандидат не совпадает с `file_title`. Исключения: подтверждён метой, является префиксом `metadata_series`, стоит перед номером тома, найден блок-матчером с score=1.0 при наличии меты.
- `_clean_series_name()`: удаление сервисных слов и диапазонов из скобок/суффиксов.
- `_remove_blacklist_words()`: удаление blacklist-слов.
- `_is_valid_series()`: итоговая валидация.

#### Шаг В: Fallback на метаданные

Если `series_candidate` пуст и `record.metadata_series` не пуст:
- Word-boundary проверка на blacklist → `_extract_series_from_metadata()` → `_clean_series_name()` → `_is_valid_series()`.
- `series_source = "metadata"`.

#### Установка `filename+meta_confirmed`

Устанавливается если `metadata_series.strip().lower() == clean.lower()`. Для иерархического root с числом: если `metadata_series` совпадает с root без числа, а подсерия числовая или дублирует метаданные — схлопывается до `metadata_series`.

---

### 2.3 Определение series_number (Pass 2)

Вызывается в конце `execute()` → `_correct_series_number_from_filename()`.

**Правило 3 (приоритетное):** явный диапазон в скобках `(т. N-M)` → `series_number = "N-M"`.

**Правило 1:** числовой префикс `NN_` или `NN.` в начале stem → `series_number = N` (не год).

**Правило 2:** `SeriesRoot[\s\-]+N[\.\s]` в середине стема → `series_number = N`. Поддерживает разделители пробел и дефис между серией и номером.

**Правило 4:** голый диапазон в конце стема `Серия N-M` → `series_number = "N-M"`.

---

### 2.4 Pass 3: Нормализация серий

**Где:** `passes/pass3_series_normalize.py`

Применяется после Pass 2. Основные шаги нормализации строки серии:

- Удаление лишних пробелов, NFKC-нормализация.
- Шаг 1.9: удаление zero-padded хвостовых номеров (`07`, `05+`).
- Шаг 1.95: удаление служебного префикса «Цикл «...»» / «Цикл "..."».
- Шаг 1.99: удаление незакрытой скобки в конце строки.
- Шаг 2: удаление номера в скобках в конце.

---

### 2.5 Pass 4: Нормализация и консенсус серий

**Где:** `passes/pass4_consensus.py` → `execute()`

Шаги выполняются строго по порядку:

| № | Шаг | Описание |
|---|-----|----------|
| 1 | Очистка ложных серий | Серия у одного файла одного автора → удалить при соблюдении условий (source=filename, не подтверждена метой, нет сервисных слов, нет числового суффикса) |
| 2 | Специальные серии | Значения из `special_series_values` в метаданных → абсолютный приоритет |
| 3 | Author consensus | `series_processor.apply_author_consensus()` |
| 4 | Series consensus | `series_processor.apply_series_consensus()` |
| 5 | Metadata series consensus | Одна уникальная `metadata_series` в папке → применить ко всем без серии |
| 6 | Proposed series consensus | Серия ≥2 раз в папке → применить к файлам без серии |
| 7 | Series author consensus | Исправить неполные авторы в серии (является подмножеством консенсусного) |
| 8 | **Валидация подсерий из filename** | Для `"X\Y"` из filename: если <2 файлов автора подтверждают Y как первый сегмент заголовка после `"X N."` → схлопнуть в "X". Запускается ДО консенсуса унификации |
| 9 | Hierarchical unification (1-й проход) | «А. Б» → «А\Б» если у автора есть базовая серия «А». Числовые суффиксы → схлопываются |
| 10 | Числовой суффикс → подсерия | `"X N"` → `"X\Y"` если у автора ровно одна подсерия с базой X |
| 11 | Singleton subseries fix | Подсерия с одним файлом → схлопнуть в базовую серию |
| 12 | Trailing number strip | `"X N"` (≤3 цифры, не год) → `"X"`, `series_number = N` (не перебивает уже заданный) |
| 13 | **Re-fix series_number from stem** | Перечитать `series_number` из стема файла по текущему `proposed_series`. Стем авторитетен если серия найдена в нём. Не применяется если серии нет в стеме |
| 14 | folder_hierarchy cleanup | Серии с embedded именем автора или из blacklist → откат к `metadata_series` |
| 15 | Filename prefix author consensus | Для [unknown] авторов |
| 16 | Multi-author series folder cleanup | Многоавторные папки → очистить `proposed_series` совпадающий с именем папки |
| 17 | Filename sequence + metadata dual confirmation | Исправить source на `filename+meta_confirmed` |
| 18 | Series suffix correction | Суффикс длинной подтверждённой серии → исправить |
| 19 | Folder metadata consensus | ≥50% файлов в папке с одной `metadata_series` → применить |
| 20 | Folder series propagation | Хотя бы один файл получил серию из папки → остальные без серии получают ту же |
| 21 | Filename phrase + metadata confirmation | N-граммы из заголовочных частей имён файлов + подтверждение метой |
| 22 | Hierarchical unification (2-й проход) | Повторный после всех консенсусов |
| 23 | Финальная нормализация ё→е | NFC + replace во всех `proposed_series` |

---

### 2.6 Иерархия подсерий (backslash-конвенция)

`proposed_series = "РодительскаяСерия\ПодсерияN"` означает вложенную серию.

- Разделитель `\` создаётся в Pass 2 (шаг 0, паттерны двухуровневой иерархии) и в Pass 4 (шаг 9).
- Подсерия считается настоящей если ≥2 файлов автора подтверждают её название в стеме (шаг 8 Pass 4).
- Компилятор обрабатывает подсерии особо: `sort_key = (0, parent_num, sub_ordinal, inline_vol)`.
- `series_number` для подсерии относится к родительской серии, не к подсерии. Компилятор проверяет этот инвариант в `_determine_sort_key()`.

## 3. Подсистема компиляции

**Ключевой файл:** `fb2_compiler.py`

### 3.1 Структуры данных

**`CompilationBook`** — одна книга в группе:
- `sort_key: Tuple[int,int,int,int]` — ключ сортировки (level, primary, secondary, tertiary).
- `sort_source: str` — источник порядка.
- `order_ambiguous: bool` — порядок не определён.
- `volume_label: str` — отображаемый номер тома («1», «1-3», «Свиток 1»).

**`CompilationGroup`** — группа для компиляции:
- `books` — список книг.
- `volume_range` — итоговый диапазон («1-7», «»).
- `duplicate_paths` — файлы к удалению.
- `kept_paths` — файлы которые остаются (для cleanup_only).
- `cleanup_only: bool` — компиляция не нужна, только удалить дубликаты.
- `part_count` — число частей при паттерне N.M.
- `series_complete: bool` — False если за пределами run'а есть другие тома.
- `alphabetical_order: bool` — порядок не определён, сортировка по названию.

**Уровни `sort_key`:**
| level | Значение | Источник |
|-------|----------|----------|
| 0 | Позиция определена | series_number / filename |
| 1 | Дата написания | `title_date` |
| 2 | Дата издания | `publish_date` |
| 9 | Неопределённая позиция | ambiguous=True |

---

### 3.2 Группировка книг (`find_groups()`)

**Ключ группировки:** `(_norm_key(author), _series_group_key(series))`

`_series_group_key()`:
- Без backslash → `_punct_norm(series)` (знаки препинания → пробел, lower, ё→е).
- С backslash и числом в корне → `"basekey|subkey"` (разные подсерии одной пронумерованной серии попадают в один бакет).
- С backslash без числа в корне → `_punct_norm(полный путь)`.

**Слияние бакетов** (итеративное до стабилизации):
Два бакета сливаются если одновременно:
- Авторы: один является подмножеством слов другого.
- Серии: одна является хвостовым суффиксом другой.
- Хотя бы одно из условий строгое (не равенство).
- Метаподтверждение: у бакета с длинной серией есть файл, `metadata_series` которого совпадает с короткой серией.
- Канонический ключ → более длинный автор + более длинная серия.

**Имя серии для группы:** если все записи принадлежат одной подсерии → полный путь (`Root\Sub`); иначе → корень без числа.

---

### 3.3 Контекстные коррекции перед фильтрацией

**1. Сервисное слово + все тома присутствуют:**
Если в группе есть файл с сервисным словом (Трилогия, Тетралогия…) в имени, а тома 1..N присутствуют по отдельности → устанавливается `series_number = "1-N"`, пересчитывается `sort_key`.

**2. Групповая коррекция meta vs filename:**
Если большинство книг используют `sort_source = "series_number"`, а меньшинство — `"filename"` → меньшинство пересчитывается по мете.

**3. Многосоставные заголовки:**
Если `file_title` содержит ≥2 точек с заглавной буквой и совпадает с ≥2 заголовками других книг группы (непрерывный диапазон) → файл считается предкомпиляцией, `series_number = "lo-hi"`.

---

### 3.4 Обработка предкомпилированных файлов (`_precompiled_range()`)

Определяет диапазон `(lo, hi)` томов в файле. `hi > lo` → файл предкомпилирован.

**Критерии (по приоритету):**

| # | Критерий |
|---|----------|
| 1 | Диапазон `N-M` в стеме или `file_title` с привязкой к серии (series_words). Ведущий диапазон в стеме принимается без проверки серии |
| 1.5 | Паттерн «N-M книги/томов» после точки |
| 1.6 | Паттерн «книги/томов N-M» перед диапазоном |
| 2.5 | Сервисное слово в стеме (Трилогия→3, Тетралогия→4…). Исключение: «Серия N (СлужСлово)» где N не входит в название серии → `(0,0)` |
| 2 | `series_number` в виде диапазона «N-M» из метаданных (запасной, не для подсерий) |
| 3 | Сервисное слово в `file_title` с привязкой к серии |
| 4 | Слово «компиляция»/«сборник» → парсинг первых 64KB |
| 5 | Многосоставный `file_title` (≥2 точек с заглавной) → парсинг первых 64KB |

**Важный нюанс:** два предкомпилированных файла с разными `series_number` никогда не считаются дубликатами друг друга, даже при пересечении диапазонов — это разные дуги серии.

---

### 3.5 Три состояния предкомпиляции

**1. АКТУАЛЬНА (`cleanup_only=True`):**
Все обычные тома покрыты предкомпиляцией, нет других непокрытых предкомпиляций → предкомпиляция остаётся, отдельные тома идут в `duplicate_paths`.

**2. ПОЛНОСТЬЮ УСТАРЕЛА:**
Все тома предкомпиляции присутствуют по отдельности → предкомпиляция в `duplicate_paths`, компилируем из отдельных томов.

**3. ЧАСТИЧНО УСТАРЕЛА:**
- Оставшиеся книги продолжают предкомпиляцию (min_remaining = best_hi + 1) → включаем предкомпиляцию как источник, покрытые тома в `duplicate_paths`.
- Оставшиеся не продолжают → `cleanup_only` для покрытых + остальные обрабатываются отдельно.

**Несколько предкомпиляций:** другие предкомпиляции → дубликаты если их диапазон полностью покрыт любой другой; иначе — дополнительные источники.

---

### 3.6 Дедупликация

**Фильтр 1: по заголовку** (`_normalize_title_key()`):
- Убирает префикс `"<Серия>. "` из `file_title`.
- NFKC-нормализация (римские Unicode → ASCII).
- Для level-0 добавляет `\x00{sort_key[1]}` — разные тома с одинаковым названием не считаются дублями.
- Приоритет при выборе «лучшего»: когерентность именного набора → схожесть с другими книгами → дата из FB2 → ключевое слово «новый вариант» → год в имени файла.

**Фильтр 2: по позиции** (`_dedup_by_position()`):
Одинаковый `sort_key` на уровне 0 → оставляем наиболее «свежую» версию (по той же схеме приоритетов).

**Фильтр 3: по содержимому** (`_dedup_by_content()`):
Параллельное чтение первых 64KB, сравнение первых 2000 символов нормализованного текста (без предисловий, URL, ©). `SequenceMatcher` ≥0.85 → дубликаты. Из пары оставляем файл с более конкретным `sort_key` (ненулевой secondary/tertiary); при равенстве — больший по размеру. Предкомпилированные файлы (`volume_label = "N-M"`) исключаются из этой проверки.

---

### 3.7 Определение порядка (`_determine_sort_key()`)

Возвращает `(sort_key, sort_source, is_ambiguous, volume_label)`.

#### Источник А: series_number из метаданных

Применяется если `proposed_series` не содержит `\` и:
- `metadata_series` не задана, или совпадает с `proposed_series`, или содержит хотя бы одно ключевое слово серии.
- `metadata_series` не добавляет значимых слов (защита от «более специфичной» подсерии).

Для целого `sn`:
- Перекрёстная коррекция: если в стеме найден другой номер (`fn_num < 1900`, `fn_num ≠ meta_num`) → возможна замена.
- Паттерн N.M (dot_part): → `(0, vol, part, 0)`.
- Roman inline ≠ meta_num → `(0, roman_inline, 0, 0)`.
- «Том N» / «Книга N» суффикс → `(0, meta_num, kw_n, 0)`.

Для диапазона `sn = "N-M"`:
- Если перед сервисным словом стоит число позиции подсерии, не входящее в название серии → `(0,0)`, не предкомпиляция.

**Для подсерий** (`\\` в proposed_series):
- `parent_num`: номер корня из proposed_series или из стема.
- `sub_ordinal`: номер подсерии в стеме или file_title.
- `inline`: «Том N» / «Книга N» из title/stem.
- Fallback для подсерий без числа в корне: ведущее число стема → sub_ordinal.
- `sort_key = (0, parent_num, sub_ordinal, inline)`.

**Дополнительная логика при `_series_ok=False`:**
Если series_number уже выставлен (например, Rule 2 из Pass 2) но `metadata_series` не совпадает с `proposed_series` → используем `series_number` напрямую, не перезапрашиваем из стема.

#### Источник Б: число в имени файла (`_STEM_NUM_RE`)

Паттерны (все anchored к началу или середине):
- `"N. "`, `"N- "`, `"N_ "`, `"N "` + заглавная — в начале.
- `" N. "` в середине.
- `"Серия N"` в конце.

Поиск secondary из остатка стема: диапазон `N-M` → `(0, num, lo_range, 0)`, label `"lo-hi"`; числовой суффикс точки → `(0, num, sec, 0)`.

#### Источники В, Г: даты из FB2

- `title_date` → `(1, year, month, day)`, `sort_source = "title_date"`.
- `publish_date` → `(2, year, month, day)`, `sort_source = "publish_date"`.

#### Fallback

`(9, 0, 0, 0)`, `order_ambiguous = True`.

### 3.8 Разбивка на runs и финальная сборка

**`_split_into_consecutive_runs()`:**
Разбивает числовые книги (level=0) на непрерывные блоки. Пробел в нумерации → новый run. Для подсерий — сопоставление по `sort_key[2]` (sub_ordinal).

**Эмиссия групп:**
- **Все ambiguous** → единая группа, `alphabetical_order=True`.
- **Числовые:** каждый непрерывный run ≥2 → отдельная `CompilationGroup`. `series_complete=True` только если нет одиночных томов за пределами run'а.
- **Эвристика «неопределённый = том 1»:** единственный файл без номера + среди числовых нет тома 1 → считается первым.
- **Нечисловые (даты/unknown):** ≥2 → отдельная группа; <2 но есть одиночный числовой (не precompiled) → объединяется с нечисловыми.

**Именование компиляции** (`_series_suffix()`):
- `lo ∈ {0,1}` + `series_complete=True` → сервисное слово (Дилогия/Трилогия/…) или «в N книгах».
- `lo ∈ {0,1}` + `series_complete=False` → «книги lo-hi».
- `lo > 1` → «т. lo» или «т. lo-hi».

**`_run_stats()`:** вычисляет `top_lo`, `top_hi`, `n_volumes` (раскрывает диапазоны из `volume_label`), `has_subseries`. Для dot_part: `n_volumes` = число уникальных томов (не частей).

---

### 3.9 Ключевые нюансы и граничные случаи

- `_punct_norm()` для ключа группировки: «Ревизор. Возвращение» и «Ревизор: Возвращение» попадают в одну группу.
- Подсерии «Серия 04\Роман» и «Серия 06\Роман» → в один бакет через `|subkey`.
- `_dedup_by_content` исключает precompiled-файлы: их начало совпадает с томом 1 по определению.
- Специальный случай: «Ибисовая трилогия 1. Маковое море» — слово «трилогия» является частью названия серии + за ним идёт номер тома → `(0,0)`, не предкомпиляция.
- `duplicate_paths` назначаются только первой группе в серии (`first_group = True`).
- `cleanup_only=True` создаётся даже если после dedup остался один файл — чтобы удалить дубликаты.
- **Предупреждение о пересечении диапазонов:** в GUI (`gui_compiler.py`) — оранжевая подсветка группы в списке + текст в нижней панели, если файлы в группе имеют пересекающиеся `volume_label`.

## 4. Взаимодействие подсистем

```
FB2-файлы
    │
    ▼
Pass 1 (scan)          — сбор метаданных из FB2
    │
    ▼
Pass 2 (series/author) — извлечение автора и серии из filename + folder
    │                    _correct_series_number_from_filename() (Правила 1-4)
    ▼
Pass 3 (normalize)     — нормализация строки серии
    │
    ▼
Pass 4 (consensus)     — 23 шага нормализации и консенсуса
    │                    финальный re-fix series_number из стема
    ▼
regen_csv.py           — экспорт в CSV для диагностики
    │
    ▼
fb2_compiler.py        — группировка, определение порядка, компиляция
    │
    ▼
gui_compiler.py        — UI: отображение групп, предупреждения, запуск
```

**Инварианты которые должны соблюдаться на входе в компилятор:**
1. `proposed_series` не содержит хвостового числа (стрипнуто Pass 4 шаг 12).
2. `series_number` соответствует позиции в `proposed_series` (не в подсерии) (Pass 4 шаг 13).
3. Подсерия `"X\Y"` существует только если ≥2 файлов автора подтверждают Y в стеме (Pass 4 шаг 8).
4. Два файла с разными `series_number` никогда не являются дубликатами в компиляторе.
